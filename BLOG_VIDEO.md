# Відео для блогу: генерация видео через Gemini

В админке (Filament) есть раздел **«Відео для блогу»**. В нём пишут сценарии-диалоги персонажей, загружают референсы и генерируют короткие вертикальные или горизонтальные видео. Сервис работает только на бэкенде: файлы лежат в `public/blog-video/`, на фронте они пока нигде не выводятся.

## Какие модели используются

| Что | Модель / инструмент | Где настраивается |
|---|---|---|
| Генерация и продление видео | **Gemini Omni 1.1 Flash** (`gemini-omni-1.1-flash`), Google Gemini API, Interactions API | `GEMINI_VIDEO_MODEL` (по умолчанию `gemini-omni-1.1-flash`) |
| Подготовка референсов | Intervention Image: ресайз до 1536 px по длинной стороне, JPEG 88, base64 | `GeminiVideoService::REFERENCE_MAX_SIDE` |
| Длительность и склейка видео | `ffmpeg` / `ffprobe` | `FFMPEG_BIN`, `FFPROBE_BIN` |

Других AI-моделей нет. Промпт собирается кодом из полей сценария, отдельная LLM для его написания не вызывается.

### Переменные окружения

```dotenv
GEMINI_API_KEY=...                  # обязательно
GEMINI_VIDEO_MODEL=gemini-omni-1.1-flash
# Цены Standard tier, USD за 1M токенов (ai.google.dev/gemini-api/docs/pricing, на 28.10.2026)
GEMINI_PRICE_INPUT=1.50
GEMINI_PRICE_OUTPUT_VIDEO=17.50
GEMINI_PRICE_OUTPUT_TEXT=9.00
# Пути к ffmpeg (на проде это статическая сборка в /opt/ffmpeg)
FFMPEG_BIN=/opt/ffmpeg/ffmpeg
FFPROBE_BIN=/opt/ffmpeg/ffprobe
```

Все значения читаются в `config/services.php`, в блоках `gemini` и `ffmpeg`.

## Сущности

| Таблица / модель | Назначение |
|---|---|
| `blog_video_characters` / `App\Models\Blog\VideoCharacter` | Персонаж: имя, описание внешности, описание голоса, до 5 фото-референсов |
| `blog_video_scenarios` / `App\Models\Blog\VideoScenario` | Сценарий. Поля ниже |
| `blog_video_reels` / `App\Models\Blog\VideoReel` | Ролик: склейка готовых видео нескольких сценариев в один mp4 (сценарии можно повторять) |

Поля сценария:
- локация (`setting`), стиль, стартовый кадр (`start_frame`);
- реплики (`lines`): персонаж, ремарка, текст;
- доп. инструкции и доп. референсы;
- язык, формат (`9:16` / `16:9`), разрешение (`360p` / `720p` / `1080p` / `4k`);
- состояние генерации, продления (`extensions`), стоимость.

Статусы сценария: `draft` → `processing` → `done` / `failed`.

## Как генерируется видео

Код: `app/Services/GeminiVideoService.php`. Кнопки в админке находятся в `app/Filament/Resources/Blog/VideoScenarios/Pages/EditVideoScenario.php`.

### 1. Сборка промпта (`buildPrompt`)

Промпт пишется по-английски, а реплики остаются на языке сценария. Из полей сценария собираются секции:

1. `A short video for a sushi restaurant blog.`
2. Если есть **стартовый кадр**, он передаётся как `<IMAGE_REF_0>` с указанием использовать его как точный первый кадр. Фото персонажей в этом случае **не передаются**: персонажи уже есть на кадре.
3. `Scene:` (локация) и `Visual style:` (стиль).
4. `Characters:` — по каждому персонажу, который участвует в диалоге (в порядке первого появления):
   - `looks exactly like the person in <IMAGE_REF_n>`, если нет стартового кадра;
   - `Appearance: ...`;
   - `Voice: ...`.
5. Доп. референсы: `Use <IMAGE_REF_n> as reference for the location, props and food.`
6. Диалог:
   - строки вида `Имя (ремарка): "текст"`;
   - реплика без текста помечается как `— silent, no speech`;
   - если говорит один персонаж, добавляется `Only X speaks; everyone else stays silent.`
7. Доп. инструкции из сценария.

Готовый промпт сохраняется в `last_prompt` и виден в админке («Промпт, відправлений у модель»).

### 2. Запуск задачи (`start`)

```http
POST https://generativelanguage.googleapis.com/v1beta/interactions
x-goog-api-key: $GEMINI_API_KEY

{
  "model": "gemini-omni-1.1-flash",
  "background": true,
  "input": [ {картинки base64...}, {"type": "text", "text": "<промпт>"} ],
  "response_format": {
    "type": "video",
    "aspect_ratio": "9:16",
    "resolution": "720p",
    "delivery": "uri"
  }
}
```

Задача выполняется в фоне. В сценарий записывается `interaction_id`, статус становится `processing`.

### 3. Ожидание результата (`refresh`)

Страница сценария сама опрашивает статус каждые 15 секунд (`wire:poll.15s`). Кроме того, есть кнопка «Перевірити статус».

1. `GET /interactions/{id}`:
   - `in_progress` / `queued` / `pending` — ждём дальше;
   - иначе из ответа берётся `usage` и считается стоимость (см. ниже);
   - статус не `completed` — сценарий получает статус `failed` с текстом ошибки.
2. В ответе рекурсивно ищется видео:
   - если оно пришло inline (base64), сразу сохраняется;
   - если пришёл `uri` (вида `.../files/{id}:download?alt=media`), из него берётся `file_id`.
3. `GET /files/{file_id}`: ждём `state = ACTIVE`, затем скачиваем через `:download?alt=media`.
4. Видео сохраняется в `public/blog-video/videos/{id}-{Ymd-His}.mp4`. Длительность определяется через `ffprobe`, статус становится `done`.

Одна генерация длится около 8 секунд видео и занимает примерно 1–3 минуты ожидания.

### 4. Продление (`extend`): видео длиннее 8 секунд

Готовое видео можно продлить кнопкой «Продовжити», задав новые реплики и инструкции. Условия:
- сценарий в статусе `done`;
- есть `interaction_id` и файл видео;
- длительность меньше 35 с (лимит модели — `VideoScenario::MAX_DURATION = 40` с).

Как проходит продление:
- Отправляется новый `POST /interactions` с `previous_interaction_id` = текущий `interaction_id` и коротким промптом:
  - продолжить сцену примерно на 8 секунд с теми же персонажами, голосами, светом и камерой;
  - голоса персонажей и новый диалог.
- Gemini возвращает **всё видео целиком**, вместе с продолжением. Если новый файл длиннее старого больше чем на 1 с, он просто заменяет старый. Если вернулся только новый кусок, он склеивается со старым через ffmpeg (`*-joined.mp4`).
- Если продление не удалось, сценарий возвращается к прежнему видео и прежнему `interaction_id` (статус `done`, ошибка показывается отдельно).
- История продлений (реплики, длительность, стоимость) хранится в `extensions`.

### 5. Ролики: видео на минуту и больше

Раздел «Ролики» (`app/Services/VideoReelBuilder.php`) склеивает готовые видео выбранных сценариев по порядку в `public/blog-video/reels/{id}-{Ymd-His}.mp4`. Работает в `app/Services/VideoTools.php`:
- сначала пробует `ffmpeg concat -c copy`;
- если форматы разные (разрешение или формат кадра), перекодирует: scale/pad, 24 fps, ресемплинг аудио, тишина для клипов без звука.

Без ffmpeg ролики не собираются: будет ошибка «На сервері не встановлено ffmpeg».

## Сценарии из ChatGPT: импорт файлом

На странице «Сценарії відео» есть две кнопки.

1. **«Промпт для ChatGPT»** скачивает `chatgpt-video-prompt.md`. Это шаблон `resources/prompts/blog-video-chatgpt.md`, в который подставлены персонажи, уже заведённые в админке, с их внешностью и голосом. В промпте описаны ограничения модели (8 с на сценарий, 1–3 короткие реплики, без титров) и точный формат ответа.
2. Промпт вставляется в ChatGPT, а в конце дописывается задача («ролик про новый сет Филадельфия, Марко хвалит, Даня пробует»). ChatGPT отвечает JSON.
3. **«Імпорт з файлу»**: JSON загружается файлом (`.json` / `.txt`) или вставляется текстом. Ответ можно вставить целиком, с блоком ```json и пояснениями вокруг: из него берётся только JSON.

Что происходит при импорте (`app/Services/VideoScenarioImporter.php`):
- Каждый элемент `scenarios` становится отдельным сценарием в статусе «Чернетка».
- Персонажи ищутся по имени без учёта регистра:
  - если такого нет, он создаётся из `characters`, а фото добавляется потом в админке;
  - у существующих описание и голос **не меняются**, если не включить переключатель «Оновити опис і голос наявних персонажів».
- Если сценариев больше одного и задан `reel_title`, создаётся ролик из них по порядку. Когда все части сгенерированы, его останется собрать.
- Если файл не проходит проверку, ничего не создаётся (всё в одной транзакции), а ошибки показываются в уведомлении.
- Если импортирован один сценарий, админка сразу открывает его.

Пример файла: `resources/prompts/blog-video-example.json`.

### Формат файла

```json
{
  "reel_title": "Название ролика или null",
  "language": "українська",
  "aspect_ratio": "9:16",
  "resolution": "720p",
  "characters": [
    { "name": "Даня", "description": "Appearance in English", "voice": "Voice in English" }
  ],
  "scenarios": [
    {
      "title": "01 — Название",
      "setting": "Scene in English",
      "style": "Camera, light, sound in English",
      "lines": [
        { "character": "Даня", "direction": "smiles", "text": "Реплика" },
        { "character": "Марко", "direction": "takes a bite", "text": null }
      ],
      "extra_instructions": null
    }
  ]
}
```

| Поле | Обязательно | Примечание |
|---|---|---|
| `scenarios[].title` | да | |
| `scenarios[].lines[].character` | да | имя персонажа; хотя бы одна реплика на сценарий |
| `lines[].text` | нет | `null` — действие без слов |
| `language`, `aspect_ratio` (`9:16`/`16:9`), `resolution` (`360p`/`720p`/`1080p`/`4k`) | нет | задаются для всего файла или для каждого сценария отдельно; по умолчанию `українська`, `9:16`, `720p` |
| `characters` | нет | новые персонажи или новые описания существующих |
| `reel_title` | нет | создать ролик из сценариев файла |

Один сценарий можно прислать и без обёртки: `{"title": ..., "lines": [...]}`.

## Генерация вручную в Google Flow

Подписка Google AI бывает дешевле API, поэтому видео можно сгенерировать в [Google Flow](https://labs.google/flow) руками и загрузить обратно. Импорта файлов в Flow нет, картинки по ссылкам он не подтягивает, поэтому референсы загружаются вручную. В сценарии есть меню **«Google Flow»** с двумя пунктами.

1. **«Експорт для Flow»**. Сценарий сохраняется, и скачивается zip `flow-{id}-{название}.zip` (`app/Services/FlowVideoExporter.php`). В архиве:
   - `prompt.txt` — тот же промпт, что уходит в API, только вместо `<IMAGE_REF_n>` в нём написано `image 1`, `image 2`…;
   - картинки, пронумерованные в том же порядке: `1-start-frame.png` или `1-marko.png`, `2-dania.png`, `3-scene.jpg`;
   - `README.txt` — какую картинку куда ставить в Flow. Стартовый кадр ставится первым кадром (Frames to Video), остальные картинки добавляются как Ingredients по порядку.
2. В Flow загружаются картинки, вставляется `prompt.txt`, после генерации mp4 скачивается.
3. **«Завантажити відео з Flow»**: загружается mp4 или mov до 100 МБ. Файл сохраняется как `blog-video/videos/{id}-{Ymd-His}-flow.mp4`. Сценарий получает статус `done`, длительность определяется через ffprobe, и видео можно использовать в роликах.

Особенности:
- Продлить такое видео через API нельзя: у него нет `interaction_id`, кнопка «Продовжити відео» скрыта. Продление делается в самом Flow (Extend), после чего финальный файл загружается ещё раз.
- Стоимость в админке не считается: её видно только в кредитах Flow.
- Livewire по умолчанию ограничивает загрузку 12 МБ. В `config/livewire.php` лимит поднят до 100 МБ, как у php-fpm и nginx на проде.

## Стоимость

Google не присылает цену в долларах, только `usage` в токенах. Стоимость считается в `GeminiVideoService::cost()`:

```
cost = ( input_tokens × 1.50
       + video_output_tokens × 17.50
       + (остальные output_tokens + thought_tokens) × 9.00 ) / 1 000 000
```

- `last_cost` — стоимость последней генерации или продления;
- `cost` — сумма по сценарию; в таблице сценариев она суммируется по всем;
- `last_usage` — сырой `usage` из последнего ответа.

Фактические цифры на 28.10.2026:

| Что | Стоимость |
|---|---|
| 8 с при 360p | ≈ $0.28 |
| Продление ещё на 8 с при 360p | ≈ $0.30 |

При изменении тарифов Google достаточно поменять `GEMINI_PRICE_*` в `.env`.
